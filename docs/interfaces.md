# 팀 인터페이스 초안

이 문서는 초기 논의용이며 구현된 API 명세가 아닙니다.
토픽·서비스·메시지 타입과 필드 이름은 담당자 간 합의 후 확정합니다.

## 공통 원칙

- 최종 상태 전이와 주행 명령은 FMS 컨트롤러가 담당합니다.
- GUI는 요청·확인 입력을 전달하고 FMS의 상태를 표시합니다.
- 로봇 구분은 `pinky_1`, `pinky_2`를 사용하며 ROS2 namespace는 `/pinky_1`, `/pinky_2`로 구분합니다.
- 고정 지점은 `STORE`, `A`, `B`, `HOME`으로 구분합니다.

## 합의할 연결

| 연결 | 전달 내용 | 확정할 항목 |
|---|---|---|
| GUI → FMS | 부품 요청, 적재 완료, 수령 완료, 재시도, 취소 | 서비스 이름·타입, 로봇/작업 ID, 중복 요청 처리 |
| FMS → GUI | 로봇 상태, 작업, 대기열, 도착 예상 시간, 오류 | 상태 JSON 필드, 갱신 주기, 연결 끊김 표시 |
| FMS ↔ 작업 배정 | 후보 로봇, 요청, 배정 결과 | 함수 또는 ROS 인터페이스, cost 식, 동점 처리 |
| FMS ↔ 도킹 | 시작, 취소, 진행, 완료, 실패 | action/서비스/토픽 선택, 시간 초과, 결과 형식 |
| FMS ↔ Nav2 | 목표 이동, 취소, 결과 | 로봇별 action 경로, 기준 프레임 |
| FMS → 알림 | 로봇별 상태 | 토픽·타입, 알림 반복·종료 조건 |

## 상태 이름

루트 README 기준으로 `IDLE`, `TO_STORE`, `WAIT_PICKUP`, `WAIT_LOAD`,
`TO_STATION`, `WAIT_RECEIVE`, `TO_HOME`, `ERROR`를 사용합니다.
구체적인 전이 조건과 오류 복구 정책은 구현과 함께 검증합니다.

## 통합 전에 결정할 사항

- Nav2에서 도킹으로 넘어갈 때 속도 명령 제어권을 전환하는 방법
- 픽업대·수납대 점유와 대기 위치, 오류 발생 시 점유 해제 방법
- 각 완료 입력의 작업 ID 검증과 중복 입력 처리
- 상태 메시지의 스키마 버전, 타임스탬프, 위치·거리·각도의 단위
- ROS_DOMAIN_ID와 로봇별 namespace 설정
